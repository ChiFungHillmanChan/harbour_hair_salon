## 2. 已確認的商業決定

1. 價目以平台原列金額為準，不自行創造價格、折扣率或促銷套餐。兩平台有差異時，沿用原先確認的 **Treatwell 優先**；Fresha 可作核對，不能混用、平均或聲稱兩者本來完全一致。例如長髮洗剪吹 NHS 使用 £45，不使用 Fresha 曾顯示的 £44。
2. **所有服務暫時保留平台原列的一般價及 NHS 價。** 一般價與 NHS 價均不再疊加網站全站優惠、優惠碼或平台額外折扣。保留優惠及優惠碼資料與管理功能，不刪除既有記錄；本期暫停其在新報價／新預約中的套用，亦不要消耗優惠碼次數。
3. NHS 項目只需簡單標示「NHS 優惠適用」／`NHS discount applies`。顧客選取 NHS 價後，摘要可顯示「已套用 NHS 價」。不新增資格說明、證件上傳或新的查核流程；不推導資格政策。沒有 NHS 價的服務不能憑空新增選項，不另顯示學生優惠。
4. **VAT：平台原列金額保持不變，不加算 VAT；新價目以「未含 VAT」／`VAT excluded` 顯示。** 不加 20%、不倒算稅額，也不稱為含稅最終總額。這是店主對網站顯示方式的指示，不代表每個平台項目的 VAT 標示都已重新核實。尤其 £37 附加費的獨立平台 VAT 標示尚未確認，資料來源紀錄要保留此差別；不要把這項顯示政策回填成歷史預約的稅項事實。
5. `Adds Extra Long` £37 是全頭染髮的特長髮附加費，以長髮價另加 £37：一般 **£157 + £37 = £194**，NHS **£142 + £37 = £179**。£194／£179 是店主確認的組合方式，不要記錄成已在平台獨立看見的兩個選項價格。
6. **£20 Special Set 暫時擱置。** 不新增搭配、獨立服務或預約加選規則，不把現有 £10 相似項目直接改名合併成它。保留來源研究資料，現有功能維持原狀；列明為本期刻意不變更項目。
7. **兩個 £15 敏感測試項目維持現有網站流程，暫不新增、合併或改變用途。** 不重新設定資格、時效或轉介規則，不聲稱費用日後可抵扣。介面及現有說明仍須翻譯。
8. **Hair Correction 在中文版也保留英文名稱。** 品牌如 Keratin、Paimore、Dr.Jr. TOKIO Inkarami 保留正確原名。
9. 先盤點實際資料；**未經本次 Treatwell 核實的舊 NHS 選項暫時隱藏並停止接受新預約**，保留已有預約、金額及歷史關聯。不能只根據 seed 猜測正式資料，也不能由 NHS 選項未核實推論整項一般服務必須刪除。
10. **可翻譯內容先儲存草稿，英文及繁體中文完成後一起發布。** 已發布內容編輯時，前台繼續使用上一個完整發布版本。
11. **電郵納入雙語範圍。** 顧客電郵使用適合該顧客／流程的英文或香港繁體中文；店方通知預設以繁體廣東話為主。店方通知中的顧客姓名、電郵、電話、備註等原始資料保留原文。

不要重新詢問以上已確認事項。一般技術選擇由你根據現有架構決定；新增業務政策或缺少來源證據時，才提出具體問題，並繼續可獨立完成的部分。

## 4. 服務資料、報價及歷史保護

建立明確的服務／髮長／價格類型關聯，使用穩定 ID；不要在執行時計價時依賴名字是否包含 `NHS`，也不要用翻譯文字配對。一次性的人工資料對應可以參考原名，但必須產生可審閱的明確對應表。

對應表包含現有服務 ID、來源項目或可定位證據、原文名稱、一般／NHS 配對、髮長、時長、價格、價格性質、稅項顯示及證據來源、版本、核對日期、公開及可預約狀態。保留 `treatwellExternalId` 等整合關聯，不將內部資料全部送入公開頁面。

實作正式的公開／新預約可用狀態，讓未核實 NHS 選項能保留歷史但停止新預約。服務列表、首頁精選、分類、搜尋、結構化資料及前後台新建預約都遵守狀態；Server Action 亦拒絕被停用的 ID。已有預約仍可查看及按現有政策取消／改期，不能因停用新選項就封鎖舊預約。

新報價必須由伺服器決定並產生版本化結果，涵蓋服務／選項 ID、一般或 NHS 類型、金額與 GBP、必要的 £37 組合明細、稅項顯示政策、價格性質及時長來源。語言不影響計價。顧客新建、任一造型師分配、管理員新建及更換服務使用相同規則。

本期所有新報價都不套額外優惠；顧客端隱藏或停用優惠碼入口，伺服器對仍提交優惠碼的舊頁面回傳清楚的暫停訊息，不暗中套用、不計次、不默默改價。服務卡、橫幅、優惠頁及電郵不得繼續宣傳實際不適用的折後價；後台保留既有優惠資料並清楚顯示暫停套用狀態。避免引入與本期無關的新促銷系統。

提交預約時重新驗證價目版本；價目已改則回傳新報價讓顧客確認，不以畫面舊金額默默建立新價預約。單純改期保留原價格條件；明確更換服務／選項時，先顯示新報價再更新快照。現有預約即使曾用優惠碼，也保留原已記錄金額，不追溯取消優惠。

更新價目前，唯讀盤點 `priceAtBooking` 空白的預約，以及涉及的通知及薪酬期間。移除把當前服務價冒充歷史成交價的回退。沒有歷史證據時保持未知，不填現價、不填零、不推論 NHS 或 VAT；顧客／後台提供清楚但不暴露內部診斷的缺失金額說明。含價格的通知不得捏造金額。依賴缺失金額的佣金重算須指出受影響資料並阻止錯誤結果，不能默默忽略該收入；既有已定案薪酬保持原有保護。

使用 Decimal 或整數便士保持計價精度，在顯示邊界格式化；不改變現有薪酬比例、時間或會計口徑。若諮詢報價無法確定為可計佣金額，列出確實受影響項目，保留原政策並等待有依據的處理，不自行引入新的薪酬規則。

資料更新工具預設 dry run，輸出新增、更新、停用、保留及未能對應的差異；可重複執行而不新增重複服務，並有事務、版本及預期舊值檢查。正式套用前不得存在不明對應或未處理的歷史金額影響。回退不得刪除歷史預約或改寫已使用的新價格快照。不執行破壞性 seed 重建。

## 5. i18n 路由、版面及語言切換

採用原草稿的設計預設：英文 `en-GB` 保留既有網址；繁體中文 `zh-HK` 使用 `/zh-hk/` 前綴，包括 admin 與 kiosk。保留既有服務／文章／造型師 slug，兩語共用元件、業務邏輯及資料模型，不複製整套網站。API、OAuth callback、cron、ICS、靜態資產維持原有路徑。

介面切換顯示 **English｜繁體中文**。公開桌面導覽、手機導覽、後台桌面側欄／手機工具列及打卡頁均有可用入口。明確網址語言優先；既有英文網址初次仍顯示英文，不按位置或瀏覽器語言強制跳轉。記住手動選擇可用於後續連結及適用的通知偏好，不覆蓋明確 URL。Kiosk 語言是裝置偏好，不冒用員工個人設定。

網站中文採香港常用詞彙的繁體書面語，英文採英式英文。店方通知使用自然的繁體廣東話。沿用現有字型方向，中文採合適系統字型回退，不預設載入大型中文字型。

語言切換保留頁面、篩選、頁碼、日期區間、錨點、服務與價格選項、預約步驟、後台未儲存表單及目前編輯的內容語言分頁。切換不提交表單、不建立預約、不重新計價。

先實作並驗證三個代表流程：BookingWizard、未儲存服務表單、MFA 設定完成後的復原碼畫面，再推廣到全部頁面。明確決定哪個共用 layout／狀態容器持續存在；不能假設路由跳轉會保留頁面 `useState`、未受控輸入或 `useActionState`。

敏感輸入、MFA setup secret、OTP 及一次性復原碼只留在必要的同頁記憶體，不放 URL、localStorage、sessionStorage 或持久快取。切換後保留原有一次性結果，不重新發起 enrollment；保持 URL、SSR 語言及瀏覽器返回／前進一致。登出或切換帳戶時清理相關暫存。若第一種路由方案不能達標，先調整架構，不以停用語言切換或丟失復原碼當成完成。

受保護頁面先辨識合法語言前綴，再按不含語言的業務路徑執行原有政策；涵蓋 middleware／proxy、頁面、Server Actions、MFA、kiosk、登入及 OAuth 跳轉。保留既有安全回跳驗證。MFA 僅翻譯現有管理員功能，不新增顧客 MFA。`/book` 及中文對應頁保留先檢查預約關閉／平台入口、再檢查登入的順序。

## 7. 內容管理與成對發布

介面語言與正在編輯的內容語言分開。每個可翻譯的內容編輯畫面提供 English／繁體中文分頁、完成度及需重新校對狀態；切換介面語言不換內容分頁、不覆寫另一語言。

翻譯記錄與原內容建立明確關聯，同一實體與語言不得重複。包括標題、描述、政策說明、SEO、alt text、分類／文章內的 JSON 區塊、FAQ 及程式內 fallback 文案；圖片、服務 ID、金額、時長、品牌、權限、slug 及規則等共享資料不要各存一份讓兩語漂移。

「儲存草稿」與「發布」分離。兩種語言的必填內容在同一修訂齊備後才能發布；修改其中一種語言的內容後，另一種的既有文字不能僅因非空就視作已校對。草稿不改動目前公開版本；發布時原子地啟用同一修訂並同步失效兩語快取。管理員能預覽未發布內容，但公開查詢與 RSC payload 不得洩漏草稿。

這項流程適用於網站自有可翻譯內容，不把員工資料、時鐘、預約異動、營業時間或純營運開關誤改成必須等待翻譯才能生效。價格及相關說明需一致發布，不讓一語顯示舊條件而另一語已使用新價。

首次雙語發布前完成所有可取得的網站自有內容翻譯及校對。若正式資料庫另有未取得內容，要輸出準確的待補內容清單與匯入方式，不把測試 seed 的翻譯聲稱為全部正式內容已完成。

## 8. 電郵、通知及匯出

翻譯預約申請、確認、取消、改期、提醒、評論邀請、密碼重設及店方新預約通知，涵蓋主旨、HTML、純文字、日期、價格類型、VAT 說明及內部連結。

採用以下明確技術預設：顧客建立預約時保存通知語言；該預約的後續確認／提醒等沿用它，不取最後操作的管理員語言。密碼重設按發起頁面語言。店方共用通知語言獨立設定且本期預設為 `zh-HK`，文案以繁體廣東話為主。個人之後更改介面偏好不追溯改寫已有預約或隊列事件。舊記錄缺少語言時使用英文相容回退。

排入 outbox 時保存事件的語言、必要翻譯內容及價格語意快照。首次發送前固定寄件內容，重試保持相同內容與冪等性；舊 payload 及已固定郵件須相容，不把新字典或新稅項政策套入舊事件。翻譯失敗或缺少新欄位不得破壞既有通知交付策略。

顧客姓名、電郵、電話及備註原樣顯示；中文店方郵件也不改寫它們。每個連結指向正確語言的網站頁面，機器 callback／unsubscribe token 等保留安全語意。不要為了測試而向真實顧客發信或開啟正式通知旗標。

翻譯 CSV 下載按鈕及說明，現有薪酬 CSV 欄位識別、數字與格式維持相容，本期不新增會隨介面語言默默變動的表頭。ICS 保持既有機器格式與通用 `Busy` 標題，不加入顧客或服務詳情。

## 9. 價目版面、SEO 與效能

桌面以服務組別及髮長清楚比較一般／NHS 價；手機使用直向排版或卡片，不靠橫向捲動才看得到 NHS 價。相應價格旁提供「未含 VAT」說明。沒有 NHS 選項只顯示一般價；不顯示零元或自行推算折扣百分比。

首頁精選、服務列表／分類、搜尋、價格區間、預約摘要、顧客詳情、後台視窗、電郵及 JSON-LD 使用同一選項與價格語意。不要把 NHS 價當成所有人適用的最低價，不在 JSON-LD 把未含 VAT 的金額宣稱為含稅最終總額。

各公開語言頁提供正確 SSR HTML lang、title、description、canonical、hreflang、Open Graph 及 sitemap。英文原 URL 保留；中文頁 canonical 指向自身，不全部指回英文。帳戶、admin、kiosk、預約與相應中文頁維持適當不索引設定；robots 不代替授權。

公開頁在伺服器載入該語言所需內容，客戶端只接收互動所需字串。不要為了語言偏好而讓所有公開頁讀取登入資訊、全站變動態渲染或增加不必要的 Neon 查詢。區分語言及發布版本的快取，更新時同時失效英文與中文相關頁面。預留語言控制空間，避免語言閃爍及字型造成 CLS。
