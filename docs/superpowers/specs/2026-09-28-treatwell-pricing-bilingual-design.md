# Treatwell 價目與全站中英文設計草稿

日期：2026-09-28

分支：`codex/core-web-vitals`

狀態：供審閱的設計草稿；尚未實作、修改資料庫或更新正式網站。

## 1. 已確認的要求

- 全站支援英文及繁體書面語，中文採用香港常用詞彙。
- 範圍包括所有公開頁面、顧客流程及管理後台頁面，並包含員工打卡頁。
- Treatwell 是唯一價格依據；照片及 Fresha 的價格不再作為網站定價依據。
- 使用 Treatwell 的一般價及已有 NHS 價；標示 Student & NHS 的選項可提供其 NHS 價，但不另外顯示學生優惠。
- 不推算 NHS 折扣百分比，也不在 NHS 價上再自動套用平台折扣。
- Treatwell 明確標示 VAT excluded 的項目，網站同樣標示「未含 VAT」。未標示的項目不自行判定為含稅或未稅。
- 額外造型採用 Treatwell 的 £20，取代先前照片方案的諮詢報價。
- 本階段只有研究及設計。所有既有程式變更保持原狀，不更新外部平台、不執行 migration、不部署。

## 2. 建議的全站體驗

### 語言選擇

切換標籤使用 **English｜繁體中文**。公開網站桌面版放在導覽列的帳戶／預約控制附近；手機版放在選單按鈕旁，展開選單亦可切換。後台桌面版放在側欄頂部，手機版放在頂部工具列。打卡頁提供獨立切換入口。

建議保留現有英文網址；繁體中文版使用 `/zh-hk/` 前綴，包括 `/zh-hk/admin` 及 `/zh-hk/kiosk`。兩種語言共用頁面及資料，不維護兩套獨立網站。內容語系採用 `en-GB` 及 `zh-HK`。

首次進入現有英文網址顯示英文；明確的網址語言優先。記住使用者手動選擇，登入後可保存個人語言偏好。暫不按地理位置或瀏覽器語言強制跳轉。員工打卡裝置的語言是裝置偏好，不冒用任一員工的個人偏好。

切換語言保留目前頁面、篩選、頁碼、日期、錨點及已選服務。預約草稿及後台未儲存表單在同一工作階段中保留；切換本身不提交表單、不建立預約、不重新計算歷史金額。敏感表單資料不放進網址或持久化至瀏覽器儲存空間。MFA 設定流程須在同一頁面工作階段保留剛顯示的一次性復原碼，不能因語言切換重新產生或遺失。密碼／MFA 輸入欄位的狀態處理須另有驗收，不得無提示地丟失已輸入資料。

## 4. 服務頁及 NHS 顯示設計

桌面版以服務組別及髮長列出「一般價格／NHS 優惠價格」，在相應價格附近顯示稅項說明。手機版採用同樣內容的直向服務卡，不依賴橫向捲動才能看到 NHS 價。

沒有 NHS 選項的服務只顯示一般價，不出現 £0 或虛構折扣。現有 NHS 與一般服務的對應必須用明確資料關聯，不依賴翻譯後的文字或名稱中是否含 NHS 作判斷。兩種語言的服務選項、金額及稅項完全共用。

預約摘要、管理員預約視窗、顧客預約詳情均需顯示適用的價格類型和稅項。既有電郵凡有顯示價格，其商業含義也必須正確；這不等同已確認全部電郵雙語化，後者仍屬第 7 節的建議延伸。只有已明確定義的金額才標作最終總額；標示未含 VAT 的數字不改稱含稅總額，也不自行推算稅率。網站目前的價格欄位不足以表達全部語意，後續實作需先明確分開基礎價、NHS 價格選項及稅項狀態。

一致性以同一價格版本及選項為準。已存在的預約保留原來記錄的金額與條件，不因更新價目而改價。現有顧客預約頁對 `priceAtBooking` 為空的舊記錄會退回使用當前服務價；因此正式更新價目前，必須先檢查這批舊記錄並確認處理方式，不捏造歷史金額、NHS 資格或 VAT 狀態。

NHS 資格及查核方式，以及是否可與現有網站優惠併用，尚待店主確認。單憑平台的 NHS 價不能推導查核政策或額外折扣。

## 5. 雙語內容管理

後台介面可以使用任一語言。服務、分類頁、造型師介紹、首頁文案、常見問題、優惠及網誌等可編輯內容，在同一編輯頁提供 English／繁體中文內容分頁，並顯示翻譯完整度。切換介面語言不自動切換正在編輯的內容欄位，也不覆寫另一語言。

共享資料：服務及預約 ID、分類識別值、價格、稅項、時長、營業時間、相片、品牌、權限、優惠及預約規則。可翻譯資料：標題、描述、說明、SEO 文字及圖片替代文字。介面字串使用受版本管理的字典；資料庫內容使用與原記錄關聯的翻譯資料。

首次雙語上線前，完成目前所有網站自有可見內容的翻譯及校對。日後可儲存未完成的草稿；建議公開內容須兩種語言齊備才作新的雙語發布。管理端可顯示英文原文與「尚未翻譯」狀態，不能把未完成的中文稿當成已核對的內容。

翻譯不執行即時機器翻譯。現有平台的錯字、重複段落及不自然的中文，按確認的服務語意重新撰寫繁體書面語。價格、政策及法律文字需另行校對，不能從行銷文字猜測。

## 6. 技術設計原則

以下是建議架構，不是已實作功能。

- 使用共用路由與語言感知的連結；保留既有英文網址及服務 slug。API、OAuth callback、cron、ICS 訂閱等機器介面保留既有網址及格式。
- 所有管理員、MFA、顧客及打卡權限在兩種語言路徑上一致。登入、登出、Google 驗證、密碼重設及跳轉都保留選定語言，回跳網址仍接受現有的安全驗證。
- 現有 `/book` 頁在登入檢查前處理預約關閉／外部預約顯示；本次語言設計保留此順序，不自行開放網站預約。
- 畫面用翻譯標籤，資料層沿用穩定狀態碼、分類識別值及 ID。搜尋能找到中英文服務名稱；權限及計算不比較翻譯後字串。
- 公開頁優先在伺服器載入當頁所需語言；互動元件只收到所需字串。語言切換位置預留空間，中文採合適字型回退，避免額外大型中文字型載入及語言閃爍。
- 金額繼續使用 GBP，預約及營運時間維持 Europe/London。語言影響顯示方式，不改變幣別、時區、日期區間、夏令時間或薪酬計算。
- 新增／修改內容後，同步失效中英文頁面的快取；快取鍵區分語言，避免一種語言的頁面渲染到另一種語言。
- 公開頁提供相符的 HTML lang、標題、描述、canonical、語言替代連結及 sitemap。兩種語言的管理、帳戶及打卡頁均保持私有與不被索引的策略；robots 設定不代替登入授權。
- 相關資料模型變更必須同步三份 Prisma schema。現有預約的價格／時長快照、關聯及平台對應保留，不刪除有歷史預約的服務後重建。
- Treatwell 定價採人工核對後受控更新。這次不設計登入憑證抓取、私有平台 API 或自動同步價格的工作。

## 7. 電郵及匯出（建議一併納入）

建議將預約申請、確認、取消、改期、提醒、評論邀請、密碼重設及店方新預約通知納入雙語，包含主旨、HTML、純文字及連結。顧客通知按該次事件的語言快照；店方共用通知地址另有明確語言設定，不取決於最後操作的管理員。

排程通知將語言與內容快照一起儲存；重試維持原有寄件內容及冪等性。既有沒有語言記錄的事件，建議採英文相容回退。

後台 CSV 下載按鈕及說明翻譯；現有薪酬 CSV 的欄位識別及數字格式維持相容。如需中文表頭，提供明確選項，不因管理員切換語言而默默改變既有匯出格式。ICS、整合欄位、原始記錄及錯誤代碼保留其機器可讀語意。對外 ICS 保留現有通用 Busy 標題，不因雙語功能加入顧客或服務詳情。

## 8. 驗收設計

1. 逐項核對 Treatwell 一般／NHS 金額、服務選項、附加項目及稅項標示，保留來源與核對日期。
2. 同一服務及所選價格版本在首頁、服務頁、新預約、後台及既有價格電郵的金額與價格類型一致；歷史預約保留原條件。不新增獨立學生優惠或臆測折扣；沒有價格快照的舊預約已有經確認的處理方式。
3. 所有上列頁面及共用狀態均以英文和繁體中文逐頁驗收，包括手機、平板及桌面後台。
4. 預約途中、排程篩選中及後台有未儲存資料時切換語言，資料及所選日期保留，沒有額外提交。
5. 兩種語言均驗證登入、MFA、權限、打卡鎖定及受保護路由，不能因網址前綴繞過保護。
6. 檢查中英文內容編輯、缺少翻譯提示、發布狀態、快取更新、搜尋及網站索引資料。
7. 如納入電郵及匯出，檢查通知語言、連結、純文字、重試及 CSV 相容性。
8. 實作時以同一測量條件比較兩種語言的效能，檢查切換控制、字型及載入造成的版面移動；不在本階段聲稱任何 Web Vitals 分數改善。

## 9. 尚待確認的業務細節

- NHS 優惠資格及店內證明要求；是否與網站其他優惠併用。
- `Adds Extra Long` £37 的具體用途與預約選取方式。
- 兩個 £15 敏感測試項目的差別，以及平台未明確標出的項目稅項。
- Hair Correction 的正式中文服務名稱。

這些問題不影響全站雙語範圍的確認，但涉及其服務的正式發布或預約計價前必須釐清。其他尚未逐項批准的架構與內容發布流程，均為本草稿的建議預設，供下一輪設計審閱。
